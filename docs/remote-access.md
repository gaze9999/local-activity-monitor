# 遠端存取入口設計

這份規格定義後續串接入口, 尚未啟用遠端存取、登入或串流服務, 現有服務維持 loopback 與 Host / Origin 限制

LAM 採 HTTP API 查詢與操作, SSE 傳送資料更新通知, WBUI 被動訂閱資料並局部更新畫面. 定時查詢保留為本機入口及串流中斷時的替代方式

## 責任與介面

| 所屬 | 入口 | 責任 |
| --- | --- | --- |
| LAM 用戶端 | `connect({baseUrl, transport, signal})` | 選擇本機 HTTP 或經驗證的遠端來源, 建立與關閉訂閱 |
| LAM 用戶端 | `query({resource, filters, cursor, limit, signal})` | 取得有界快照或歷史頁面, 驗證版本與欄位 |
| LAM 用戶端 | `subscribe(listener)` | 接收 `{revision, resources}` 更新通知, 合併重複通知後只查詢受影響資料 |
| LAM 用戶端 | `saveSettings({value, revision, signal})` | 保存目前使用者的設定, 版本衝突時回報並重新取得設定 |
| WBUI | `createStore(value)` | 保存目前畫面資料, 依 selector 與相等判斷通知訂閱者 |
| WBUI | `reconcileChildren(root, items, options)` | 保留未變動元素, 更新順序與受影響項目 |

表格與圖表不直接開啟遠端連線, WBUI 不管理登入、Token、帳戶、API 位址或歷史資料庫

## 通知與恢復

### 本機與遠端共用的更新流程

本節同時涵蓋目前本機後端與前端, 後續遠端沿用相同資料更新介面. 本輪只納入設計, 現有定時 HTTP 查詢仍為實際傳輸方式

1. 收集器完成一批資料的交易寫入與統計投影後, 後端發布完整可查詢的資料版本, 再發送通知, 不在交易提交前宣告新資料可用
2. SSE 通知只帶 `instance_id`、`revision` 與 `resources`, 例如對話、SQL、MCP、來源狀態或設定, 不傳完整快照或訊息本文. 每批發布一個版本, 來源狀態即使沒有新增活動也可獨立變動
3. 前端在短時間合併通知, 合併變動範圍並保留最新版本. 查詢目前分頁、可見卡片與已開啟明細所需要的資料, 其他分頁標記待更新, 開啟時才查詢. 同一資源只保留一個有效查詢, 新通知在查詢期間到達時安排下一輪, 不丟失尚未取得的版本
4. LAM 將結果送入畫面資料 store, WBUI 更新受影響的卡片、表格與圖表. 以穩定識別碼保留元件、分頁、排序、篩選、捲動位置與已開啟的 modal, 插入或移出項目沿用共用動畫及減少動態效果設定. 新資料使目前頁碼超出範圍時才調整頁碼, 已移除的明細顯示可理解的狀態

資料版本、程式版本與前端資產版本分開. 後端重啟以新的 `instance_id` 識別, 前端重新取得目前畫面快照並恢復訂閱, 不因此重新載入整個頁面. 舊來源或舊查詢的結果不得覆寫新的來源狀態, 回應須標示實際讀取的版本, 版本仍落後於通知時繼續查詢

通知佇列保持有界, 慢速用戶端合併為最新版本與變動範圍. 若事件位置已過期或無法確認連續性, 發送需要重新同步的通知, 前端重新查詢目前畫面需要的快照. 心跳只證明通訊存活, 不增加資料版本. 前端在背景時可暫停資料查詢並累積變動範圍, 回到前景後合併查詢

實作驗收需涵蓋提交後通知、短時間多批合併、查詢期間再收到通知、重複及缺漏事件、後端重啟、來源切換、HTTP 備援與 SSE 恢復, 並核對分頁、捲動、modal、鍵盤焦點與圖表設定保留. SSE 連線管理與資料相依屬於 LAM, WBUI 維持通用 store 與元件更新能力

每個畫面共用一條 SSE 連線, 以單調遞增的事件識別碼及資料 revision 去重. 通知只包含資料型別與版本, 不包含提示詞、回應正文或憑證. 使用者切換分頁後只查詢目前需要的資料

正常斷線使用 SSE 重連. 伺服器不再保有對應通知位置時要求重新取得快照, 不能把缺漏通知視為資料已同步. 連線失敗後退回有上限的定時查詢, 顯示離線或等待狀態, 恢復後關閉重複輪詢

登入與關閉畫面時須取消查詢與訂閱. 遠端服務須實作 HTTPS、使用者權限隔離、明細存取控制、CSRF / Origin 驗證、請求與連線上限, 並確認代理不緩衝事件串流. 不直接放寬目前 loopback 檢查

## 遠端登入與裝置配對

建議採首次短碼配對、日常 Passkey 登入, 配對與登入分開管理. 本節為候選設計, 尚未實作, 代碼長度、有效期限與工作階段期限為初始建議值, 後續需按部署環境驗證

| 方式 | 用途 | 優點 | 條件與取捨 |
| --- | --- | --- | --- |
| 短碼配對 | 新裝置第一次取得權限 | 主機與遠端畫面容易操作, 不需先有帳戶服務 | 主機端須核准, 短碼不能作為長期登入憑證 |
| Passkey | 配對後的日常登入 | 不需記憶密碼, 可使用裝置解鎖或安全金鑰 | 須固定 HTTPS 網域與 RP ID, 依瀏覽器及驗證器支援選擇 |
| 每次短碼配對 | 臨時裝置或 Passkey 無法使用時 | 使用後可直接撤銷 | 每次需主機操作, 不適合無人值守 |

主機擁有者先在本機開啟「新增遠端裝置」, 產生一次性 8 位數配對碼, 建議有效 5 分鐘. 遠端裝置輸入主機 HTTPS 位址與配對碼, 主機再顯示該次請求的識別資訊與雙端相同的確認值, 由擁有者確認裝置及權限. 裝置名稱由用戶端提供, 不視為身分證明

配對碼只綁定這次交易, 嘗試次數有全域及交易上限, 建議每筆最多 5 次, 到期、拒絕或成功後立即失效. 配對完成須以不可猜測的獨立交易秘密取得工作階段, 不能只憑短碼查詢結果或領取憑證. 禁止公開遠端入口自行建立首位擁有者, 不讓未登入的網路請求核准配對

配對取得一次性的註冊權限後, 遠端使用者可建立 Passkey. 伺服器驗證 challenge、Origin、RP ID、使用者驗證結果與交易期限, 保存公開金鑰與必要 credential metadata, 不保存生物辨識資料或私密金鑰. 日後以 Passkey 驗證成功建立工作階段, 新增憑證與提升權限須重新驗證或由擁有者核准

遠端工作階段使用同來源 Secure、HttpOnly、SameSite Cookie, 設定閒置及最長期限, 每次 API 與 SSE 均驗證使用者、來源及權限. 登出或撤銷裝置立即撤銷工作階段並關閉串流, 不把 Session Token 放在 URL 或 localStorage. 初期建議區分唯讀資料與修改設定權限, 對 SQL / 工具明細另做權限檢查

Passkey 遺失時, 可從仍有管理權限的裝置或本機擁有者入口撤銷並重新配對. 遠端不能只憑短碼自行重設擁有者. 實作前需選定 HTTPS 網域、RP ID、驗證套件與工作階段期限, 不手寫 WebAuthn 密碼學驗證

WebAuthn 的憑證依 RP ID 綁定, 遠端部署應先確定穩定網域. 參考 [W3C WebAuthn 規格](https://www.w3.org/TR/webauthn-2/). 短碼流程參考 [RFC 8628 的期限、猜測限制與使用者確認原則](https://www.rfc-editor.org/rfc/rfc8628.html), 此處是 LAM 裝置配對設計, 未宣告支援 OAuth Device Authorization Grant

## 遠端裝置連線狀態

遠端模式在右上角加入「遠端裝置」狀態, 與 LAM 服務、Codex 來源、保存天數及回補進度分開. 本機模式隱藏遠端裝置項目. 狀態使用文字及圖示, 不只用顏色區別, WBUI 提供通用狀態元件, LAM 決定連線含義

| 顯示狀態 | 判定 | 畫面行為 |
| --- | --- | --- |
| 等待配對 / 等待核准 | 尚未取得工作階段 | 顯示配對流程, 不載入受保護資料 |
| 連線中 | 已開始驗證及連線, 尚無成功通訊 | 保留明確等待狀態 |
| 已連線 | 已授權, 最近通訊成功且未超過存活門檻 | 顯示目標名稱與最近收到資料時間 |
| 重新連線中 | 串流中斷, 正在有界重試 | 保留已載入資料並標示資料可能尚未更新 |
| 已連線, 定時更新 | 串流中斷但 HTTP 備援成功 | 顯示備援更新方式, 不冒稱即時串流正常 |
| 已離線 | 串流與 HTTP 均失敗, 或連續超過存活門檻 | 保留既有畫面, 顯示最後成功時間與重試操作 |
| 登入已失效 | 工作階段過期、裝置被撤銷或權限回覆為 401 | 停止重試與訂閱, 清除受保護畫面資料, 提供重新登入 |

右上角額度依來源實際回報顯示, 只有週額度時只顯示週額度, 同時提供 5 小時與週額度時兩者都顯示, 短視窗在前. 建議直接標示各自的視窗名稱、剩餘比例及重設時間, 例如「5 小時 72% · 週 40%」, 不把不同視窗相加或據登入方案推算缺少的額度

連線狀態以服務端心跳、成功的 API 回應及錯誤事件更新, `navigator.onLine` 只作提示, 不證明服務可用. 通訊存活與資料更新時間分開, 沒有新活動但心跳正常仍屬已連線, 有舊資料也不能推定已連線. 403 表示該資源無權限, 不直接改成整體離線或登入失效

點擊狀態開啟連線資訊, 顯示目標、目前裝置名稱、登入身分、權限、傳輸方式、最近成功通訊及資料更新時間, 可重新連線、登出. 管理裝置及撤銷權限只對擁有管理權限的使用者開放. 不在右上角暴露 Token、配對碼或完整敏感位址

狀態更新只通知受影響的元件, 同一來源只保留一個連線狀態 owner. 登出、切換來源與關閉畫面取消既有請求與 SSE, 避免舊連線事件覆寫新目標狀態. 實作驗證需涵蓋首次配對、拒絕與期限、斷線恢復、HTTP 備援、工作階段失效、權限拒絕與裝置撤銷

## 設定與語言

遠端設定由伺服器按使用者及來源保存, 以版本判斷避免不同裝置互相覆寫. `localStorage` 保留外觀快取與尚未同步的選擇, 不保存存取憑證, 設定匯出仍使用有版本的 JSON

後續語言檔按 `zh-TW`、`en`、`ja` 與穩定訊息識別碼管理, 可依語言載入. WBUI 保存共用元件訊息, LAM 保存產品訊息, 使用者自訂文案保存為獨立設定. 目前 LAM 英文與日文仍共用 `frontend/locales.json`, 繁中原文仍在 HTML / JS, WBUI 通用字串仍在程式內

首次啟動引導另外設計, 本輪不實作. 遠端入口亦未宣告為現有可呼叫 API

SSE 是單向通知, EventSource 預設會重連, HTTP/1.x 的多分頁連線數需要控制, 遠端部署宜驗證 HTTP/2. 參考 [MDN SSE 文件](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events), 雙向即時互動需求可再評估 [WebSocket](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API)
